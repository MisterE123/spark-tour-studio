# Collision scalability review

Reviewed 2026-10-19. This is a proposed next architecture, not a claim that streamed collisions are included in this release.

## Findings

SuperSplat is a useful reference for **sparse voxel collision**. Its documented format stores a sparse octree in a JSON header and binary file, with 4×4×4 voxel masks at leaves. Empty space and fully solid regions compress well. Its current viewer nevertheless fetches the entire binary with `arrayBuffer()` before constructing its collider; streamed splat rendering and streamed collision are separate features. A paged collision format would therefore be additional work for Spark Tour, rather than something enabled by adopting that loader. Sources: [format specification](https://developer.playcanvas.com/user-manual/splat-transform/voxel-format/), [current loader](https://github.com/playcanvas/supersplat-viewer/blob/main/src/collision/voxel-collision.ts#L921), [PlayCanvas announcement separating walk mode and streamed LOD](https://blog.playcanvas.com/new-in-supersplat-walk-mode-streamed-lod-and-easy-upload/).

The SuperSplat viewer and splat-transform use the MIT license. Reusing compatible parts is possible with their notices preserved. This does not change the decision to avoid copying the separately licensed Lichtfeld extension. Sources: [viewer license](https://github.com/playcanvas/supersplat-viewer/blob/main/LICENSE), [splat-transform license](https://github.com/playcanvas/splat-transform/blob/main/LICENSE).

Our current generator has real, deliberate limits: 100,000 footprint columns, five million solid voxels, 32 million dense grid samples, two million output triangles, and a 160 MiB GLB validation limit. A sparse accumulation stage becomes a dense bounding box in `CollisionGrid.finish()`. Widely separated selected areas can consequently exhaust it even when each area is small. Smooth extraction adds a float32 copy and filtering/marching-cubes allocations to that dense grid. Raising the numbers would trade visible limits for unpredictable memory exhaustion.

The viewer then downloads/parses the complete GLB, builds a Rapier triangle collider, and starts Recast route preparation. Persistent route caching already helps repeat visits; it does not remove the initial complete collider download and physics construction. The recorded Tourv2 benchmark in `TEST_RESULTS.md` found approximately 1.08 seconds for physics and 5.22 seconds for cold routes on a 1.52-million-triangle collider, before allowing for all other startup tasks. This is one local case, not a Quest performance prediction.

## Selection performance fix in this release

Previously every selected shape or numeric transform change destroyed and rebuilt all selection meshes. Drag tint previews also put new matrix literals into a new Spark shader every 100 ms. This could repeatedly compile GPU programs while moving a handle.

Selection meshes and box-wall handles now retain their identity and geometry while their transforms change. A fixed 10 KiB float texture carries ordered shape matrices and add/remove flags to one stable shader. Choosing a different shape only updates its outline and handles; it does not recalculate the splat tint. Clearing selection releases the texture and meshes. The shader still evaluates the active volumes against rendered splats, so many overlapping volumes on a large scene can remain expensive; this change removes unnecessary compilation and allocation rather than making that work free.

Regression checks compare packed selection against CPU selection for rotated boxes, balls and ordered add/remove operations, and verify that 50 preview updates retain the shader and geometry. Existing native collision-editor and box-wall interaction checks should remain part of release verification.

## Recommended next design

Adopt **paged sparse collision tiles**, while retaining GLB import and existing projects. Keep collision detail independent of the splat rendering level of detail. A low-detail visual splat must never become a missing wall in physics.

1. Offer an explicit generation scope: **Entire scene** or **Selected areas**. Entire scene consumes every original RAD leaf page without requiring BALL/BOX selections; Selected areas applies the ordered add/remove regions in scene coordinates. Preserve authored regions when changing scope so the choice is reversible. Existing projects default to Selected areas; an empty selection must never silently turn into whole-scene generation. Optionally allow exclusions in whole-scene mode, clearly separate from the required selection mask. Both scopes use the same opacity filtering, meter scale, sparse tile format and bounded worker pipeline. A sparse block map should be the canonical intermediate, with no scene-wide dense allocation. Store filled runs or collapsed solid blocks where appropriate; empty space between features must cost little memory. Whole-scene means the occupied splat surfaces, not a filled box around the scene.
2. Partition that sparse result into fixed spatial tiles. Use a small versioned manifest containing coordinates, bounds, voxel resolution, entry points, tile URLs, sizes, hashes and neighboring tiles. Compress each tile's occupancy with an octree or packed sparse blocks. Include overlapping border samples to prevent holes or seams during local surface extraction. Start with separate relative tile files: they work with the existing folder export, CDN configuration, HTTP caching and cancellation, and do not require range support from every host.
3. Initially retain Rapier movement: load collision tiles around the viewer and build merged local collision faces for those resident tiles in a worker. That permits gradual integration and preserves crouching, stairs, slopes, wall sliding, jump and drone collision behavior. Load the starting neighborhood first. Retain a safety ring beyond the maximum per-frame motion and unload only outside a larger radius, with a bounded memory budget. Treat unavailable or failed tiles as unavailable movement space; never allow a visitor to fall through while data arrives.
4. Generate and save navigation tiles during authoring, using the same collision hash, character dimensions and settings. The viewer should load nearby route tiles rather than rebuilding an entire scene's navigation on first arrival. Cross-tile routing needs adjacency and a coarse region graph. Keep local refinement for narrow paths. This addresses the route-preparation delay as well as geometry downloads; changing storage alone does not fix pathfinding startup.
5. Add the collider behind a common query interface used by walk/drone movement, valid-start searches, head safety, path picking and bubble occlusion. Direct octree capsule/sphere sweeps can then be compared with local Rapier meshes without rewriting UI or navigation twice. A direct backend should ship only after it matches step/slope/sweep behavior and large-delta collision tests. Coarse occupancy alone is not a replacement for continuous collision detection.
6. Extend project/export validation for the new manifest and all reachable tiles, with checksums and relative/CDN resolution. Existing GLB colliders remain supported, and an optional full GLB export remains useful for external tools. Do not silently regenerate or convert existing authoring data when opening an old tour.

The specified SuperSplat binary can be a useful interchange/import format, but its global 24-bit child indices are not independently fetchable pages. Splitting its bytes arbitrarily would break references. A native tile manifest can instead carry self-contained octrees, or a dedicated range index would need to be designed and validated.

## Prototype acceptance gate

- Generate disjoint, kilometer-spanning authored regions and a dense small interior without a global dense grid; record peak memory, selected splats, occupancy blocks, generation time and output size.
- Compare cold entry-to-movement time and peak memory on the same large real tour, desktop and physical Quest 3/3S, using an empty browser cache and throttled networking.
- Verify capsule seams, slopes, stairs, narrow corridors, multi-level floors, crouch/jump, high-speed drone movement, transformed scenes, and invalid starts across tile borders.
- Exercise rapid scene changes and teleport targets outside the resident neighborhood. Verify cancellation, bounded caches, XR session continuity and no movement into unloaded collision.
- Verify paths and bubble/head occlusion across resident tiles, disconnected authored regions, failed requests, offline portable export, subdirectory hosting and a separate asset origin.

Recommendation: make this a measured follow-up collision release. Ship the concrete selection optimization with the UI work, and prototype sparse generation plus initial-neighborhood loading before replacing the established movement backend.

Whole-scene acceptance must include a capture larger than the current dense-grid limits, generation with no authored shapes, disconnected occupied areas separated by large empty space, cancellation/resume, and consistent desktop/Quest tile residency. Compare both scopes over the same region and confirm matching occupancy at the same detail. The manifest must retain generation scope and filter settings for reproducible updates.
